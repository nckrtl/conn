# nckrtl fork of T3 Code

This is Nick's fork of [pingdotgg/t3code](https://github.com/pingdotgg/t3code)
at [nckrtl/conn](https://github.com/nckrtl/conn), shipped as Conn. Read this file before you
merge upstream, build, or change shared UI. Upstream's `AGENTS.md` still
applies to everything else.

## Branch and build

- `main` is the only long-lived branch. It holds every customization. New
  work lands on `main` directly. Until 2026-10-11 this line was the `nckrtl`
  branch of `nckrtl/t3code`; the old `nckrtl` and `rooms-patches-*` branches
  are history, and `upstream-mirror` is the old upstream copy. Do not build
  from them or commit to them. `wip/*` branches hold unreviewed saved work.
- Conn tracks upstream `main`, synced every night so each sync stays small.
  The Grok bot runs the nightly sync with the procedure below; a manual sync
  follows the same steps.
  Merge `upstream/main` into a sync branch (`sync/<yyyy-mm-dd>`) off `main`,
  then merge that back after a good build. Do not merge upstream's preview or
  stable tags: they are cut on release branches, not on upstream `main`, so
  the next sync merges their cherry-picks again. Never force-push `main`.
- The Mac desktop app, the iPhone app and the T3 servers (beast, mini, shark
  and the headless server on nick) all run Conn builds from `main`. Server
  runtimes are built with `scripts/build-cli-archive.ts`.
- Build, sign and install: [.agents/skills/nckrtl-shell-design/references/build.md](.agents/skills/nckrtl-shell-design/references/build.md).
  Builds ship no update feed (`publish: null` in
  `scripts/build-desktop-artifact.ts`), so the app never replaces itself with
  an upstream release. macOS builds are re-signed with a local identity
  (`scripts/sign-macos-local.ts`).

## Keep the customizations through an upstream merge

1. Merge `upstream/main` into the sync branch and resolve every conflict;
   do not stop on conflicts. Make the best possible attempt to keep all of the
   fork's work and take in as much of upstream as you can. Conflicts are
   expected in the files listed above, most often `index.css`,
   `components/ui/*`, `ChatView.tsx`, `RightPanelTabs.tsx`, settings components
   and the sidebar. Keep the fork's side for styling and fork features, and
   re-apply upstream's logic and new features around it. Never drop a fork
   feature or an upstream fix to make a merge clean. Use the
   [nckrtl-shell-design skill](.agents/skills/nckrtl-shell-design/SKILL.md) as
   the rules for every UI conflict. Commit the resolution with a message that
   lists each conflicted file, how it was resolved, and which resolutions are
   uncertain.
2. Run the regression scan in the skill's "Upstream sync procedure" on
   upstream's diff. New upstream UI must follow the fork's shell rules (glass
   popovers, `ToolbarGroup`, `text-ui`, shell dividers, `scrollbar-inset`).
   Fix what the scan finds on the sync branch, before the build.
3. Lint and typecheck only the touched scope (`vp lint <files>`,
   `tsc --noEmit` in `apps/web`), and run the tests for the fork areas you
   touched (`vp test run src/laravelToolbar`, `src/annotations`, the
   workspace logic tests, `apps/desktop` `src/window`). Always run the fork
   guard `apps/mobile/src/native/connForkPatches.test.ts`.
4. Build, sign and install as described in `build.md`. Merge the sync
   branch into `main` only after a good build.

### Vendored dependency patches

Upstream vendors some dependencies as tarballs in `apps/mobile/deps`, which
pnpm patches cannot target. Conn keeps its changes to them as patch files and
ships a rebuilt tarball next to upstream's:

- `react-native-screens`: `patches/react-native-screens-conn.patch` adds a
  search field accessory (a toolbar menu item shown inside the toolbar search
  field) and a `fontSize` prop for the search bar. `scripts/build-conn-react-native-screens.ts` applies it to upstream's
  tarball and writes `react-native-screens-<version>-conn.tgz`;
  `apps/mobile/package.json` points at that file.

After a merge that bumps upstream's tarball, keep upstream's new tarball,
delete the old `-conn.tgz`, run `node scripts/build-conn-react-native-screens.ts`,
point `apps/mobile/package.json` at the new `-conn.tgz` and run `vp install`.
If a hunk no longer applies, port the change to the new upstream sources,
regenerate the patch with `diff -ruN a b` from the two extracted `package`
directories, and rebuild. The guard test fails while any of this is missing.

Rollback is cheap: `main` changes only after a good build, the sync
merge's first parent (`<merge>^1`) is the previous tip, and the install keeps
a backup of the previous app. If an automatic merge damaged fork work, revert
the merge (`git revert -m 1 <merge>`) and redo the sync by hand.

When something in this table changes (a new fork feature, a removed one, a
moved file), update this file in the same commit.
